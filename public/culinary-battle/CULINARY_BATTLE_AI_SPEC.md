# Инструкция для ИИ: создание HTML-игры «Кухня шефа Линя»

## 1. Роль и конечная задача

Ты — senior frontend-разработчик, гейм-дизайнер и арт-директор. Создай законченную браузерную игру для практики китайских иероглифов через приготовление блюд.

Игра должна:

- работать как статический сайт на GitHub Pages;
- использовать только HTML, CSS и JavaScript без обязательного сервера;
- корректно работать на компьютере, планшете и телефоне;
- сохранять прогресс через `localStorage`;
- выглядеть как современная авторская китайская кулинарная школа;
- быть мультяшной и выразительной, но не слишком детской;
- сохранять китайский характер без туристических клише;
- использовать изображения, созданные специально для проекта;
- иметь понятную образовательную механику, а не быть обычной викториной.

Не ограничивайся макетом. Реализуй полностью работающие переходы, выбор ингредиентов, проверку рецептов, прогресс, справочник, сертификаты и финальный свободный режим.

## 2. Технические ограничения

Создай статическую структуру:

```text
culinary-battle/
├── index.html
├── styles.css
├── game.js
├── CULINARY_BATTLE_AI_SPEC.md
└── assets/
    ├── Приветственный экран.png
    ├── backgrounds/
    ├── certificates/
    ├── dishes/
    ├── ingredients/
    ├── themes/
    └── vessels/
```

Правила реализации:

- Не используй сборщик, React, Vue и серверную часть.
- Не подключай платные API во время игры.
- Не помещай секретные ключи в JavaScript.
- Все пути к файлам делай относительными, чтобы сайт работал из подпапки GitHub Pages.
- Не используй внешние изображения с нестабильными URL.
- Шрифты можно подключить через Google Fonts, но должен быть системный запасной стек.
- Основная логика должна работать даже при недоступности внешних шрифтов.
- Не перезагружай страницу между игровыми экранами.
- Все экраны реализуй как состояния одного приложения.

## 3. Главный визуальный принцип

Визуальная система должна быть основана на существующем файле:

```text
assets/Приветственный экран.png
```

Этот файл является главным стилевым референсом. Не перерисовывай и не растягивай его.

Из него нужно взять дизайн-язык:

- тёплая рисовая бумага;
- глубокий киноварно-красный лак;
- тонкие золотые рамки;
- тёмное ореховое дерево;
- приглушённый нефритовый цвет;
- тушевые горы и мягкая фактура бумаги;
- объёмные кнопки с золотой окантовкой;
- мягкие контактные тени;
- крупная редакционная типографика;
- аккуратные китайские печати и орнаменты.

Не использовать:

- ярко-красный фон на весь экран;
- избыток фонариков;
- драконов, панд и случайные пагоды;
- дешёвые градиенты в стиле презентаций;
- плоские прямоугольные кнопки без состояний;
- разный стиль кнопок на разных экранах;
- растянутые изображения блюд;
- эмодзи вместо полноценных элементов интерфейса.

## 5. Приветственный экран

Используй `assets/Приветственный экран.png` целиком с сохранением пропорции `16:9`.

```css
.welcome-poster {
  width: 100%;
  height: 100%;
  object-fit: contain;
}
```

Запрещено использовать `object-fit: fill` или менять соотношение сторон.

На нарисованные карточки трёх уровней наложи настоящие прозрачные HTML-кнопки. Кнопки должны быть доступны с клавиатуры и иметь `aria-label`.

На нарисованную кнопку «Начать готовить» также наложи настоящую HTML-кнопку.

Активный уровень обозначай аккуратной золотой светящейся рамкой вокруг соответствующей карточки.

### Где разместить «Меню шефа» и «Авторскую кухню»

Эти элементы не должны лежать поверх лица, тела или руки шефа и не должны закрывать блюда.

Лучшее решение — отдельная горизонтальная навигационная планка под изображением приветственного экрана:

```text
┌──────────────── полноформатное изображение 16:9 ────────────────┐
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
┌────────────── нижняя навигационная планка ───────────────────────┐
│  菜单 Меню шефа        Прогресс 0/25        Авторская кухня 🔒   │
└──────────────────────────────────────────────────────────────────┘
```

Планка должна:

- находиться за пределами изображения;
- иметь фон тёмного орехового дерева или светлой рисовой бумаги;
- использовать те же красно-золотые кнопки;
- не перекрывать шефа;
- на мобильном экране переходить в две строки;
- показывать состояние блокировки Авторской кухни;
- после разблокировки менять серую печать на золотую.

Не размещай эти кнопки плавающими поверх правой половины изображения.

## 6. Уровни сложности и инструкции

После выбора уровня и нажатия «Начать готовить» обязательно открой отдельный экран инструкции. Только после инструкции игрок выбирает тему.

### Уровень 1 — «Ученик шефа»

Текст инструкции:

> Перед вами 5 заказов. Для каждого блюда нужно выбрать ровно 2 ингредиента из 6 предложенных.
>
> На карточках показаны иероглифы, пиньинь и перевод. Неверный продукт после проверки исчезнет, а правильные ингредиенты останутся в посуде.
>
> Ошибки не завершают игру. За блюдо, приготовленное с первой проверки, начисляется больше очков.

Кнопка: `Понятно — выбрать тему`.

### Уровень 2 — «Знаток рецептов»

Текст инструкции:

> Приготовьте 5 блюд. В каждом рецепте необходимо найти ровно 3 ингредиента среди 8 вариантов.
>
> На карточках показаны иероглифы и пиньинь. Русский перевод скрыт. Неподходящие продукты исчезают после проверки, а правильные остаются.
>
> Количество попыток не ограничено. Чем меньше ошибок, тем выше итоговый результат.

Кнопка: `Я готов — выбрать тему`.

### Уровень 3 — «Мастер вока»

Текст инструкции:

> Вас ждут 5 сложных заказов. Для каждого блюда нужно выбрать ровно 4 ингредиента из 10 предложенных.
>
> В заказах и на карточках показаны только китайские иероглифы: без пиньиня, перевода и языковых подсказок.
>
> Ошибочный ингредиент исчезает, а игра продолжается, пока рецепт не будет собран правильно.

Кнопка: `Принять вызов`.

Для скрытия информации используй `display: none`, а не `visibility: hidden`, чтобы в карточках не оставались пустые промежутки.

## 10. Изображения ингредиентов

Самая важная техническая правка: в посуду должен лететь сам ингредиент, а не карточка и не квадратный фрагмент спрайта.

Для каждого ингредиента создай отдельный PNG с прозрачным фоном:

```text
assets/ingredients/tomato.png
assets/ingredients/cucumber.png
assets/ingredients/tea-leaves.png
assets/ingredients/apple-slices.png
...
```

Требования к изображениям:

- прозрачный фон;
- один подготовленный к готовке ингредиент;
- не целое яблоко, а дольки яблока;
- не чашка чая, а чайные листья;
- не упаковка продукта;
- не тарелка с готовым блюдом;
- мультяшно-реалистичный стиль;
- мягкий студийный свет;
- одинаковый угол обзора;
- единый масштаб;
- без текста, рамки и фона;
- без водяных знаков.

Пример промпта для генерации:

```text
Use case: stylized-concept
Asset type: transparent ingredient cutout for a Chinese cooking educational game
Primary request: sliced ripe tomato pieces prepared for cooking
Style: polished semi-realistic editorial cartoon, tactile food texture, not childish
Composition: centered isolated ingredient, consistent three-quarter top view
Lighting: soft warm studio light, gentle contact shading within the object
Background: genuinely transparent
Constraints: ingredient only, no plate, no bowl, no package, no text, no border, no watermark
```

Сделай отдельный запрос для каждого ингредиента. Не генерируй все продукты одной таблицей, если потом невозможно получить настоящий прозрачный вырез.

## 11. Карточки ингредиентов

Карточка ингредиента содержит:

- прозрачный PNG продукта;
- иероглифы;
- пиньинь, если разрешён уровнем;
- перевод, если разрешён уровнем;
- индикатор выбора.

Изображение внутри карточки:

```css
.ingredient-cutout {
  width: 76px;
  height: 76px;
  object-fit: contain;
  filter: drop-shadow(0 6px 7px rgba(50, 28, 16, 0.18));
}
```

Не используй `background-size` для растягивания продукта.

## 12. Анимация полёта ингредиента

Никогда не клонируй `.ingredient-card`.

  const flyer = sourceImage.cloneNode(true);

  flyer.className = 'flying-ingredient';
  flyer.removeAttribute('id');
  flyer.removeAttribute('alt');
  flyer.setAttribute('aria-hidden', 'true');

  const start = sourceImage.getBoundingClientRect();
  const target = cookingVessel.getBoundingClientRect();

  flyer.style.top = `${start.top}px`;
  flyer.style.width = `${start.width}px`;
  flyer.style.height = `${start.height}px`;

  document.body.appendChild(flyer);

  const x = target.left + target.width / 2 - start.left - start.width / 2;
  const y = target.top + target.height * 0.45 - start.top - start.height / 2;

  requestAnimationFrame(() => {
    flyer.style.transform = `translate(${x}px, ${y}px) scale(.58) rotate(-8deg)`;
    flyer.style.opacity = '.55';
  });

  setTimeout(() => {
    flyer.remove();
    addIngredientToVessel(ingredientId);
  }, 520);
}
```

  border: 0;

```

Проверь визуально: во время полёта не должно быть видно рамки, белого квадрата, иероглифов, пиньиня или перевода.

## 13. Проверка рецепта и ошибки

Жизней в игре нет.

Не показывай:

- сердечки;
- точки жизней;
- число оставшихся попыток;
- экран проигрыша из-за ошибок.

Игрок может проверять рецепт неограниченное количество раз.

После нажатия «Готовить»:

1. Сравни выбранные ID с требуемыми ID текущего уровня.
2. Если набор полностью верный — покажи готовое блюдо.
3. Если есть лишние ингредиенты — выдели только лишние.
4. Лишние ингредиенты в посуде должны потемнеть, дать небольшой дым и исчезнуть.
5. Соответствующие ошибочные карточки должны исчезнуть из сетки текущего заказа.
6. Правильные ингредиенты должны остаться выбранными и остаться в посуде.
7. Игрок добавляет только недостающие ингредиенты.

Пример:

```js
const wrongIds = [...selectedIds].filter(
  id => !requiredIds.includes(id)
);

wrongIds.forEach(id => {
  burnIngredientInVessel(id);
  removeIngredientCard(id);
  selectedIds.delete(id);
});
```

Не очищай весь `selectedIds` после ошибки.

- Правильный продукт остаётся.
- Жизней нет.
